# Changelog

All notable changes to MioROM will be documented in this file.

## [1.1.0] — 2026-09-18

### Added
- **Nintendo Game Boy Advance (GBA) ROM Engine (`miorom.platforms.gba.rom` / `miorom.platforms.gba` / `miorom.rom.handlers.gba`)**:
  - Implemented analytical parser, builder, header inspector, complement checksum recalculator, cartridge memory capacity manager, backup save detector/patcher, and deep multimedia/sound engine scanner for Game Boy Advance ROM images (`GBARom`, `GBARomHandler`, `resolve_gba_region`, `create_synthetic_gba_rom`, `fix_gba_checksum`, `GBAHeaderStruct`) with 100% zero external dependencies.
  - Implemented declarative 192-byte header binary structure (`GBAHeaderStruct`) strictly via `miorom.core.schema.BinaryStruct` ensuring unified binary schema compliance without raw `struct` calls.
  - Added header complement checksum calculation, validation, and in-place fixing (`calculate_header_checksum()`, `is_header_checksum_valid()`, `fix_header_checksum()`) implementing the hardware-exact complement formula `chk = (SUM_{0xA0..0xBC} - 0x19) & 0xFF`.
  - Added entry point decoding (`entry_point`), resolving the 24-bit relative ARM branch opcode at offset `0x00` to physical ARM cartridge space (`0x08000000..0x09FFFFFF`).
  - Added Nintendo GBA product code regional territory resolver (`resolve_gba_region`) identifying Japan (`J`), USA / English (`E`), Europe (`P`), Germany (`D`), France (`F`), Italy (`I`), Spain (`S`), Australia (`U`), and Worldwide releases from the 4th character of the Game Code.
  - Added cartridge capacity expansion and trimming (`expand()`, `trim()`), supporting power-of-two cartridge sizing from 1 MB up to 64 MB with hardware-accurate `0xFF` padding (representing erased NOR/NAND flash memory).
  - Added cartridge backup media detection and automated SRAM patching (`detect_save_type()`, `patch_save_to_sram()`), identifying EEPROM, SRAM, FLASH512, and FLASH1M signatures and converting backup calls to standard 32KB SRAM for flashcarts and emulators.
  - Added Real-Time Clock (RTC) library signature detection (`has_rtc`, `SIIRTC_V001`) integrated directly into `detect_save_type()` and `GBARomHandler` metadata.
  - Added Nintendo logo in-place restoration (`fix_logo()`), restoring the mandatory 156-byte logo bitmap (`0x04..0x9F`) required by the GBA Boot ROM.
  - Added 32-bit GBA memory pointer operations and surgical relinking (`ptr_to_offset()`, `offset_to_ptr()`, `find_pointers()`, `relink_pointers()`), enabling seamless translation relocation across Game Pak waitstate spaces (`0x08`, `0x09`, `0x0A`, `0x0B`, `0x0C`, `0x0D`).
  - Added direct GBA BIOS software interrupt (SWI) scanner bridge (`scan_swi_calls()`), resolving embedded calls to BIOS routines (`LZ77UnCompWram`, `CpuSet`, `RegisterRamReset`, etc.).
  - Added deep asset and sound discovery scanners (`find_lz10_streams()` for Nintendo LZ77 compressed graphics and text streams; `find_sappy_songs()` integrating with `SappyScanner` for Music Player 2000 song table candidate discovery).
  - Added synthetic GBA ROM fixture generator (`create_synthetic_gba_rom()`) supporting custom title, game code, maker code, save types, RTC, LZ10 streams, and Sappy tables for 100% isolated unit testing without copyrighted binaries.
  - Registered `GBARomHandler` in `RomManager` with high precedence ahead of generic cartridge fallbacks.

- **Nintendo MSBT Text Engine `MSBTFile` — UTF-8 control tag `\x0E` string truncation on null arguments, `ATR1` attribute section omission, unlabelled string drop, and non-destructive custom section preservation (`miorom.text.msbt`)**:
  1. *UTF-8 Dialogue Control Tag Truncation*: In `MSBTFile.from_bytes()`, UTF-8 strings were read with `sec_data.find(b"\x00", off)`. In official Nintendo MSBT format, control tags in UTF-8 begin with `0x0E`, followed by a 6-byte header (group ID, tag ID, and argument length as uint16) and `arg_len` argument bytes. Whenever any parameter inside the control tag (e.g. font color, wait frames, player variables, speed) contained a zero byte (`0x00`), `find()` stopped prematurely at the null byte inside the control tag, truncating the sentence and permanently destroying all dialogue text after the tag. Fixed by parsing the control tag header and skipping `7 + arg_len` bytes in UTF-8 mode, ensuring string parsing only terminates at authentic dialogue null delimiters.
  2. *`ATR1` Attribute Section Omission & Dropped Message Attributes*: `MSBTEntry` declares `attributes: bytes = b""`, but `MSBTFile.from_bytes()` completely ignored `ATR1` sections, leaving all message attributes empty. Furthermore, `to_bytes()` hardcoded `section_count = 2`, dropping `ATR1` and destroying any custom sections (e.g. `TSY1` style tables, `NLI1`, `ATO1`), which caused games like *Super Mario Galaxy* and *The Legend of Zelda* to crash upon loading repacked MSBTs. Fixed by parsing `ATR1` entries into `MSBTEntry.attributes`, generating `ATR1` during `to_bytes()` whenever attributes are present, preserving all unrecognized sections in `other_sections`, and dynamically computing `section_count = len(sections)`.
  3. *Unlabelled Dialogue String Loss*: `from_bytes()` previously built entries solely by iterating over `labels`. If an MSBT file contained strings in `TXT2` without corresponding labels in `LBL1` (or if label entries were sparse), unlabelled strings were silently discarded, shifting subsequent string indices and breaking game dialog lookups. Fixed by mapping all strings $0 \le i < \text{str\_count}$, resolving to existing labels or fallback `STR_{i}`. Added regression tests in `tests/test_text_bmg_msbt.py`.

- **`PointerRelinker.relink` — free-space search colliding with pointer tables (`miorom.text.pointer_relinker`)**: In ROMs filled with the designated fill byte (e.g. `0xFF`), `find_free_space()` could allocate memory inside the pointer table range, corrupting subsequent pointers during batch relinking. Now raises `ValueError` when `ord(ch) > 0xFF`.
- **`JapaneseCharMapMiner.search_kana_word` — 2-byte search skips unaligned ROM offsets (`miorom.text.japanese_charmap`)**: In 2-byte search mode, candidate positions stepped by 2 bytes, missing 16-bit Japanese character sequences located at odd byte offsets (e.g. following 1-byte command opcodes). Updated search to advance by 1 byte.
